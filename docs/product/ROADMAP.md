# Lumi 路线图（Roadmap）

把散落在 [`Lumi_v0_PRD.md`](PRD.md)、[`ARCHITECTURE.md`](../architecture/ARCHITECTURE.md) 与各设计文档中的线索，
整理成以「**能上架的 MVP**」为锚点的分阶段路线。逐条需求与状态见 [`REQUIREMENTS.md`](REQUIREMENTS.md)；
专题设计见 [账号/迁移/交换/IM](../design/DESIGN-accounts-and-exchange.md)、[变现](../design/DESIGN-monetization.md)、
[BaaS 选型](../design/DESIGN-baas-selection.md)；iOS 系统能力设想见 [`ios-native-capabilities.md`](../release/ios-native-capabilities.md)。

> **北极星**：占据竞品最弱的「**记忆 / 共创**」象限——完整形态 = 明信片/交换日记 + 好友共享 + AI 故事片。
> **原则**：每阶段只在**前一阶段核心假设被验证后**才推进；未验证则修回路，而非堆功能。
> **平台**：**Android 是确定目标，短期先 iOS**——由此账号/同步走跨平台 BaaS（不走 CloudKit）、变现首发即接 RevenueCat。

## MVP — 上架首版（iOS · 纯本地 · 无账号）

**目标**：用真实用户验证「集邮回路」的留存，以及「明信片分享」的自传播意愿。
**关键特征**：纯本地、无账号、无后端（沿用 v0 架构，成本近零）；登录/联网一律不需要。
**执行排期**（批次拆解 / 顺序 / 上架 Gate）见 [`MVP-PLAN.md`](../release/MVP-PLAN.md)。

### 范围内（IN）— 大多已实现，重点是打磨到上架质量

| 模块 | MVP 内容 | 备注 |
|------|----------|------|
| 点亮 | 点阵地球 + 真实地图点国家快速点亮 + 选年份 | ✅ 已实现，体验打磨 |
| 时间线 | 列表 + 足迹编辑 + 详情 | ✅ 已实现 |
| 成就/徽章 | 3 列网格、置顶可取消、可点击看「怎么得到」 | ✅ 功能就绪；水晶徽章 + **6 枚大洲大师插画徽章**（06-27）已落地 |
| 心愿单 | 真实地图点选标记 + 个人页入口 | ✅ 已实现 |
| 相册导入 | 按位置自动生成足迹（城市/国家粒度） | ✅ 已实现 |
| 小组件 | 点亮计数 + 去年今日 + **去过的国旗（独立小组件）** + 设置页小组件介绍 | ✅ 全部已实现；文案跟随系统语言 |
| 明信片 | 导出/打印 + **口令/二维码「打开自动接收」**（纯本地带外传输）；3 样式 + 3 邮票；正面随图比例自适应（16:9/3:4/1:1）；**邮戳仅收件人可见**；**节日限定章**（按地区+寄出日期匹配，MVP 内置 6 款） | 高价值自传播，无后端，纳入 MVP |
| 多语言 | 中/英/阿 + 阿语 RTL（跟随系统） | ✅ 已实现，英/阿待校对 |
| 设置 | 个人页顶部入口 + 语言（跟随系统） | ✅ 已实现 |

### 范围外（OUT，留给后续阶段）
账号/同步/迁移、好友/IM/通讯录邀请、共同行程/交换日记、推荐/行程规划、
本地模式（谷歌评价·美食家勋章）、Android、AI 故事片。

### 待定（Stretch，可压入 MVP 或紧随其后）
- **视频上传（≤3min）+ 时间线静音自动播放**：纯本地可做，但增存储/复杂度 → 建议作为 **Plus 功能 / 快速跟进**。
- **谷歌店铺 Share Extension 导入**：纯本地、价值高，但触及谷歌内容合规 → 建议 v1.x（或 MVP stretch）。

### 变现（MVP 决策）
纯本地即可卖 VIP（StoreKit 2，entitlement 在端上，恢复购买绑 Apple ID），**不需要账号**。
- **首发即接 RevenueCat**（Android 确定目标，避免日后重做计费层）。
- **建议**：MVP 的 paywall 保持**轻**（高清导出/打印、全部明信片模板、国旗等额外小组件、地图皮肤），
  核心集邮回路免费，先不伤留存验证；待留存站稳再加厚 Plus。
- 详见 [`DESIGN-monetization.md`](../design/DESIGN-monetization.md)。

### 进入 v1 的门槛
真实用户**留存达标**（核心回路被验证）+ 出现明确的「多端 / 想带走数据」诉求。

## v1.1 — 轻互动「Lumi 邮局」（小服务成本，上架后首个更新）

**目标**：把 MVP 的带外收发升级为**站内直投**——寄出的明信片"真的寄到"对方收件箱，
不再依赖复制口令/扫码；同时保留带外通道（离线 / 陌生人分享）。这是 v1.x 共创的最小可行前置。

### 选型（怎么最省）

| 方案 | 成本 | 结论 |
|------|------|------|
| 纯带外（现状） | ¥0 | 已在 MVP；互动感弱于"寄到" |
| CloudKit 公共库 | ¥0（Apple 送） | ❌ Android 断头路（确定目标），通道要重做 |
| Firebase Spark | $0 起 | 可行但与既定 Supabase 方向分裂 |
| **Supabase Free（选定）** | **$0 起**（500MB DB / 1GB 存储 / 5 万匿名 MAU），增长后 Pro $25/mo | ✅ 匿名登录开箱即用；**同一项目直接长成 v1.2 的账号/同步底座**，零迁移 |

### 机制（无账号也能收发 · ✅ 已按此落地，细节见 [DESIGN-v1.1](../design/DESIGN-v1.1-lumi-post.md)）
- ~~匿名 sign-in~~ → 实现为更省的**零 Auth 能力密钥**：首启 RPC 开箱得两码——`box_id`（邮箱号短码，公开可寄）
  + `read_token`（读取密钥，仅本机）；客户端只可调 4 个 RPC，anon 无表权限。
- **寄**：「寄给」填名字 + 邮箱号（或从往来的人点选）→ **直寄即默认寄送方式**；payload 复用口令编码（含压缩封面）。
- **收**：App 启动/回前台/明信片墙下拉 → `fetch_mail`（轮询，**不做推送**）→ 走现有入库幂等流程。
- **旅友码**：对方邮箱号/头像/国籍随卡自动攒进「往来的人」；收到的卡一键**回寄**。
- **送达回执**：足迹详情「已送达 ✓ / 已寄出·等待送达」（n/m）。
- 护栏：能力密钥 + 载荷上限 + 每箱每日限量 + 30 天 TTL（pg_cron，**待 ICY 启用**）。

**v1.1 剩余**：双机验收（DESIGN §7）· pg_cron TTL 启用 · 发版时 WhatsNew 文案 · 已知限制：换机/重装丢
read_token 即丢邮箱号（设计内，v1.2 账号绑定解决）。

## v1.2 — 账号 + 同步（BaaS）+ 资源商店开张 + 跨平台变现

**前提**：MVP 留存成立。目标：让数据「多端可用、可带走」，商店开张，变现跨平台。

- **账号**：BaaS Auth（Apple + Google 登录归一）；**v1.1 的匿名身份原地升级绑定**（邮箱号/往来关系无损保留）；登录永远可选，不挡本地使用。
- **同步 + 迁移**：跨平台 BaaS（倾向 Supabase，见选型文档）；首次登录把本地 SwiftData 按 UUID **无损认领**，
  之后双向同步（本地仍作离线缓存）。
- **资源商店**（[`DESIGN-store.md`](../design/DESIGN-store.md)）：远程 manifest + Storage 下发；商店页/包详情；
  混合制权益（常规包 Plus 免费领、限量/联名包单点购买 `com.lumi.pack.<id>`）；明信片**正面素材**品类首发
  （插画模板/画框/滤镜）；购买记录云端化。
- **跨平台变现**：RevenueCat 把已购权益绑到账号，为后续 Android 共享 Plus 打底。
- 前置技术验证：[BaaS 同步 spike](../design/DESIGN-baas-selection.md#5-poc-验证拍板前)。

## v1.3 — 共创（原 v1.x）

**前提**：v1.1 已有通道、v1.2 已有身份。

- ~~明信片站内闭环~~ → **已前置到 v1.1**（Lumi 邮局直投）。
- **创作者上架**：商店（v1.2 开张）接 UGC 投稿——上传 → 审核 → 上架分成（[`DESIGN-store.md` §7](../design/DESIGN-store.md)）。
- **共同行程**：双人/多人共享一个 `Trip`（BaaS 共享 + 行级权限）。

  （零成本过渡：MVP 期也可先做**带外版**——复用明信片口令机制互发日记，体量 S，可随时插队。）

## v2 — 好友 · IM · Android · 本地模式 · 推荐 · AI

**前提**：共创带来自然增长。完整产品形态收口（强依赖后端 + 合规）。

- **好友图谱 + App 内 IM**：发送地点/店铺/明信片消息；通讯录邀请。
- **Android 客户端**：复用同一 BaaS 与数据模型。
- **本地模式**：与全球模式并存的「本地生活」模式，按到店打卡点亮、产出「美食家」等品类勋章。**采用零成本路线**（见下「本地生活模式设计草案」）。
- **推荐 / 行程规划**：推荐旅行地 / traveler；行程规划。
- **AI 旅行故事片**：基于足迹+照片+心情自动生成回顾（可端侧 Foundation Models）。
- **星球生活（探索向 💡）**：在本地 / 全球之外加「星球生活」模式——模拟登陆月球 / 火星等星球，
  做一本**星球护照**、盖各星球**登陆印章**。纯虚拟收集向，呼应护照 + 邮票 / 邮戳收集体系，
  适合装饰内购 / 季节限定。详见 [REQUIREMENTS §11](REQUIREMENTS.md#11-星球生活模拟登陆其他星球)。
- **时间长河（探索向 💡）**：**时间维度**的穿越打卡——沿时间长河回溯到古文明/历史时期，收集古代元素的
  时代章与古票、集一本**时空护照**；与星球生活构成"空间 × 时间"虚拟收集双线，限时开放时代复用节日章
  窗口期机制。详见 [REQUIREMENTS §12](REQUIREMENTS.md#12-时间长河模拟穿越时空打卡)。

## 本地生活模式设计草案（零成本路线 · v2，已与 ICY 定方向）

**目标**：在「全球点亮」之外加一个「本地生活」模式——到店打卡、攒品类勋章、看本地时间线。**先走零成本路线**（无付费 API、无后端、可离线），验证玩法后再决定是否加点评数据。

### 取数：零成本
- **发现/找店**：用 Apple **`MKLocalSearch` / `MKLocalPointsOfInterestRequest`**（已在 `Lumi/Services/PlaceSearch.swift` 用）。免费、零 Key、端上直出、可离线缓存结果。给：店名、品类（餐厅/咖啡/景点…）、坐标、电话、网址。
- **明确不做（A 期）**：评分 / 别人的评论 / 店铺照片——**没有任何免费来源**，且 Google/Yelp 有计费与展示存储限制。留到 B 期再按需接（仅在店铺详情页实时拉、带署名、不落库），可做成 Plus。
- 用户自己的打卡照片用本机相册（与现有 `Footprint` 照片一致），零成本。

### 模式切换（架构）
- App 级模式开关「全球 ⇄ 本地生活」，存 `@AppStorage("lumi.mode")`；**地图 / 成就(勋章) / 时间线三 Tab 都按 mode 读对应数据源**。
- 复用现有抽象：地图走 `MapProvider`（本地模式下钻到城市/街道级 + POI 图钉）、统计走 `LumiStats` 的本地变体。

### 数据模型 & 勋章
- 新增 `@Model VenueCheckIn`（店铺打卡：名称、品类、坐标、日期、可选照片/评分自评/备注），与 `Footprint` 平级、同一本地容器。
- 新增本地勋章规则（`BadgeCatalog` 的本地变体）：美食家、探店达人、咖啡猎人、城市百店等——按 `VenueCheckIn` 的品类/数量/连续天数评估。
- 本地时间线 = `VenueCheckIn` 列表（复用现有 Timeline/详情/分享卡 UI 思路）。

### 分期
- **A 期（零成本，可独立验证）**：MapKit 找店 + 自家打卡 + 本地勋章 + 本地时间线 + 模式切换。无 Key、无后端、可离线。
- **B 期（按需点评）**：验证成立后，店铺详情页按需接 Google/Foursquare 拿评分/评论/照片（带署名、不缓存正文），做成 Plus。
- 仍属 **MVP 之后**；不进 MVP 一期（一期保持纯本地集邮回路打磨上架）。
