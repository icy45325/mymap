# Lumi 商业设计：VIP 变现 × 账号

> 方向性设计文档。配合 [`DESIGN-accounts-and-exchange.md`](DESIGN-accounts-and-exchange.md)（账号/迁移/同步）
> 与 [`ROADMAP.md`](ROADMAP.md) 阅读。无代码改动；评审后按 [§8](#8-落阶段) 拆任务回填 [`REQUIREMENTS.md`](REQUIREMENTS.md)。

## Context（为什么写这篇）

Lumi 要上应用市场并做 **VIP 版**，但首版是**纯本地、无账号**（见账号文档）。ICY 的核心疑问是：

> 「VIP 先上架时没有用户体系、数据只存本地，之后再加账号——这条变现路径走得通吗？」

**结论先行：走得通，且不必为了卖 VIP 而提前自建账号。** 下面把「免费/付费边界」「不靠账号怎么收费」
「账号化之后怎么承接」「合规」一次讲清。平台前提：**Android 是确定目标，短期先 iOS**——这影响计费基础设施选型。

---

## 1. 变现原则

- **不伤害核心爽感**：「手动点亮那一下」是免费体验的核心，免费版必须能完整跑通**集邮回路**，付费只卖**增益**。
- **隐私即卖点，不上广告、不卖数据**：与「个人/家庭记忆」定位一致；广告会廉价化记忆产品。
- **local-first 不设墙**：登录与联网永远可选，不挡住纯本地使用。
- **付费优先盖住「会产生成本的能力」**：云同步、AI 故事片、视频存储、社交——这些有后端/算力成本，天然适合放进 Plus。

---

## 2. 关键结论：VIP **不需要**自建账号

App Store / Google Play 的内购本就**自带「身份」与「恢复」**，不需要你自己的用户系统：

- **StoreKit 2**：购买凭证在**端上校验**，entitlement（是否 Plus）存本地；「恢复购买」绑 **Apple ID**。
  → **纯本地版即可销售 VIP，零后端。**
- **强烈建议：从第一个付费版就接 [RevenueCat](https://www.revenuecat.com/)**（跨平台订阅/entitlement 抽象层）。
  理由——**Android 是确定目标**：
  - 一套 SDK 同时管 App Store + Google Play 的购买、恢复、entitlement；
  - 帮你把「是否 Plus」抽象成一个跨平台开关，日后**绑到自有账号、跨 iOS/Android 共享 VIP** 几乎零改造；
  - 小规模近乎免费（有免费额度）。
  - 即便首发 iOS-only 也值得接——避免上 Android 时重做计费层（与「不走 CloudKit 避免二次迁移」同理）。

## 3. 收费模式

| 模式 | 采用 | 说明 |
|------|------|------|
| **Lumi Plus 订阅（月 / 年）** | ✅ 主力 | 承载持续更新的增益（同步/AI/社交/新模板）。年付给折扣。 |
| **终身买断（Lifetime）** | ✅ 可选并行 | 满足「讨厌订阅」的用户；定价 ≈ 2–3 年订阅。 |
| **一次性装饰内购** | 🔵 后续 | 明信片模板 / 地图皮肤 / 徽章皮肤等纯装饰包，非必需。 |
| 广告 / 卖数据 | ❌ | 与隐私定位冲突。 |
| 限免 + 内购解锁 | 🔵 备选 | 即下方 freemium 切分。 |

推荐：**Freemium + Lumi Plus 订阅（含终身买断选项）**，首发先把订阅跑通，装饰内购作为后续增量。

## 4. 免费 vs Plus 功能切分

> 原则：**免费版＝完整集邮回路**；**Plus＝记忆/共创/炫耀的增益 + 会消耗后端成本的能力**。

| 能力 | Free | Plus |
|------|:----:|:----:|
| 地图点亮 / 真实地图点选 / 时间线 / 基础详情 | ✅ | ✅ |
| 基础徽章与成就 | ✅ | ✅ |
| 1 个基础小组件 | ✅ | ✅ |
| 全部小组件（含国旗模式）/ 自定义 | — | ✅ |
| 明信片：全部模板 + 高清导出 + 打印 + 口令/二维码分享 | 基础模板 | ✅ 全部 |
| 地图高级皮肤 / 主题 | — | ✅ |
| 视频上传（≤3min）与时间线自动播放 | — | ✅ |
| 进阶统计 / 年度回顾深度 | 基础 | ✅ |
| 云同步 + 多设备 + 跨平台（就绪后） | — | ✅ |
| 交换日记 / 共同行程（就绪后） | — | ✅ |
| AI 旅行故事片（就绪后） | — | ✅ |
| 本地模式「美食家」等品类勋章（接谷歌评价） | — | ✅ |

> 切分可调；核心是**免费版手感完整、不被反复弹窗打断**，Plus 的价值点清晰可感。

## 5. 定价与地区

- **地区定价（App Store Price Tiers）**：针对中东 / 全球分别定价；阿语市场单独评估购买力与支付习惯。
- **首单转化**：7 天免费试用（introductory offer）+ 年付显著折扣（如「年付省 40%」）。
- **锚点**：用「终身买断」做高锚，凸显年订阅的性价比。
- **展示**：清晰的 paywall（价值点 + 价格 + 恢复购买入口 + 条款），符合两家商店规范。

---

## 6. 账号化之后怎么承接（与账号文档衔接）

| 阶段 | entitlement 归属 | 行为 |
|------|------------------|------|
| 首发（纯本地） | Apple ID（StoreKit/RevenueCat） | 购买即解锁；换机靠「恢复购买」 |
| 加账号 + Android（v2） | 自有 user（RevenueCat 绑定） | 登录后把已有购买 **link 到账号** → iOS/Android **共享同一 Plus 权益**；本地数据按账号文档无损认领 |

- 因为首发就用 RevenueCat，绑账号只是「把 RevenueCat 用户 alias 到你的 user id」，**不需要让老用户重新购买**。
- 跨平台权益靠 RevenueCat 聚合 App Store + Play 凭证，无需自建计费后端。

---

## 7. 合规要点

- **数字商品必须走 IAP**（App Store / Google Play 规则），不能用外部支付绕开（除符合各商店例外政策）。
- **订阅披露**：自动续订条款、价格、周期需在 paywall 明示；必须提供**恢复购买**。
- **试用/促销**：introductory / promotional offer 按商店规范配置。
- **社交功能**：一旦上交换日记/IM，触发 Apple **2026 年中**起的儿童安全与年龄分级问卷（见能力纪要）。

## 9. 开放问题 / 待拍板

- **订阅 vs 买断的主次与定价点**（含中东市场定价）。
- **Free / Plus 的功能边界**——尤其「视频」「本地模式美食家勋章」放免费还是 Plus。
- **中东支付方式 / 结算**是否有 App Store 之外的诉求（一般无，IAP 即可）。
- **VIP 与「数据所有权」叙事**：纯本地 + 隐私可作为 Plus 的价值点之一，需文案化。
