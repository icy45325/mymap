Lumi Product Spec

轨迹视图 · 航线 / 火车 / 航行 / 自驾

版本 v0.1 草案 · 2026-08-29 · 作者 icy · 载体 Lumi iOS（SwiftUI + SwiftData，离线本地） · 状态 待评审
一句话 在世界地图上，把一次旅程的各个地点按交通方式分段连成线——飞机走大圆弧、火车走轨线、轮船走海路、自驾走公路——形成可查看、可筛选、可播放的旅行轨迹。轨迹与既有的「点亮地图 / 护照入境章」共用足迹数据，是收藏体系的自然延伸。

1背景与目标

1.1 现状与问题

  • Lumi 现有「点亮世界地图」把去过的地方渲染成一个个发光的点 / 面（Footprint 足迹点、国家着色），但点与点之间没有连接——用户看不到「我是怎么一路走过来的」。
  • 护照的入境章已经区分 entryMeans（air / land / sea），说明「怎么到达」是产品已有的语义，但这个信息目前只体现在盖章图标上，没有在地图上被可视化。
  • 用户对「旅行轨迹 / 航线图」有强收藏与晒图诉求（类似里程航线图、火车旅行图），这正是 Lumi「把旅程变成收藏」的延伸。

1.2 目标

目标衡量优先级
把足迹连成按交通方式区分的轨迹线4 种方式各有独立线型/颜色/图标，可在地图上区分P0
独立轨迹视图，可按交通方式切换/筛选顶部切换「全部 / 航线 / 火车 / 航行 / 自驾」，即时显隐对应线P0
手动录入一段航段（起终点 + 方式 + 日期）3 步内完成一段录入并即时上图P0
轨迹播放动画（图标沿线移动）点播放，标记沿可见轨迹依次滑行一遍P1
里程 / 段数统计，接入成就按方式累计总里程与段数，展示在轨迹视图与成就页P1
纯离线、纯本地、不采集数据无网络请求；数据存本地 SwiftData；Data Not Collected 不变P0

1.3 不包含（Out of Scope）

不做原因
真实路网 / 铁路线 / 航道数据吸附本期画线为示意性曲线（见 §5），离线优先，不接第三方路网/海图
GPS 实时轨迹自动记录 / 后台定位与「本地 + 隐私优先 + 不常驻定位」定位冲突；本期为手动录入
多人轨迹叠加 / 好友同行合并后续版本；本期只画自己的轨迹
轨迹导出为 GPX / 分享长图P2，另立需求（可复用明信片/分享体系）
Android / Web 端本期仅 iOS；跨端另议

3数据模型 · Leg 航段

按评审结论：新增独立 Leg（航段）实体，与 Footprint 解耦——一段轨迹的交通方式属于「两点之间的这一程」，而非某个到达点。Leg 挂在 Trip 下，与现有实体并列。

3.1 实体关系

一个 Trip 拥有一组 Leg（trip.legs），也拥有一组 Footprint。Leg 的起终点可可选关联到已有 Footprint（直接吸这个点的坐标与城市名），也可只存自身坐标（用户地图选点/搜索得到，不点亮）。

3.2 Leg 字段定义

坐标一律以 WGS-84 存储（与 Footprint 一致）；显示前由 MapProvider.displayCoordinate 决定是否转 GCJ-02。产品层只关心以下字段：

字段类型说明约束
idUUID唯一标识唯一
modeString 枚举交通方式：flight / train / sea / car必填
fromNameString起点显示名（城市/地点）必填
fromLat / fromLonDouble起点坐标（WGS-84）必填
toNameString终点显示名必填
toLat / toLonDouble终点坐标（WGS-84）必填
departAtDate出发日期（用于排序 / 播放顺序）必填，默认今天
arriveAtDate?到达日期可空；空=当日
noteString一句备注（航班号/车次/心情，自由文本）可空
fromFootprintID / toFootprintIDUUID?可选关联的足迹点可空
distanceKmCacheDouble?大圆距离缓存（统计用，见 §8）派生，可空
createdAt / updatedAtDate创建/修改时间带默认值 → SwiftData 轻量迁移
与现有 schema 的衔接 LumiStore.schema 追加 Leg.self；Trip 增加 @Relationship legs:[Leg]（删 Trip 时 .nullify，Leg 不随之消失、只脱离归属）。新增实体走 SwiftData 轻量自动迁移，无需数据搬运。

3.3 entryMeans 枚举细化（护照联动）

为让入境章也能区分火车 / 自驾，Footprint.entryMeans 由 air/land/sea 细化为与 Leg.mode 对齐的 4 值。旧数据 land 迁移为 train 还是 car 无法判断——

迁移策略（待确认，见 §13-Q1） 建议：旧 land 一律保留为一个兼容值 land（入境章仍显示🚆通用陆运图标），新数据才写 train/car；不强行猜测旧记录。air→flight、sea→sea 直接对齐。

本期示意性曲线：不吸附真实路网，用统一的几何规则表达「陆 / 空 / 海」的观感差异，纯离线可算。

航线flight虚线渐隐弧#5AA9E6两点大圆弧，向外侧凸起；端点淡入淡出✈️

6.2 展示与筛选

  • 全部（默认）：显示所有方式的轨迹，端点复用足迹点发光样式。
  • 单方式筛选：顶部方式 chip 可多选显隐（点「全部」= 一键全开/全关）；筛选只改显隐，不改数据。
  • 空态：无任何 Leg 时，地图中央提示「记录你的第一段旅程」+ 一个 ＋ 按钮（见 §9 E0）。
  • 层级：轨迹线在国家着色之上、足迹发光点之下，避免盖住点亮态。

6.3 轨迹播放（P1）

项规则
顺序按 departAt 升序把当前可见的 Leg 串起来依次播放
标记方式对应图标（✈️/🚆/⛴️/🚗）沿线滑行，尾迹渐隐
时长整段约 6–10s（与段数相关，单段封顶）；可再点暂停
结束停在终点，标记淡出；不改变筛选状态

8里程与统计（P1）

  • 每段里程用大圆距离（Haversine）估算，写入 distanceKmCache；示意曲线不代表真实路程，统计口径统一标注「直线估算」。
  • 轨迹视图底部小结：总里程 · 段数；按方式细分（✈️ 9,800 · 🚆 1,200 · ⛴️ 800 · 🚗 680 km）。
  • 成就页新增卡片：各方式累计里程 / 段数，可作为新徽章的解锁条件（如「万里飞行」）。徽章具体阈值另议。

10平台适配与隐私

项说明
端本期仅 iOS（SwiftUI）。轨迹视图为地图 Tab 子视图，不新增底部 Tab（现有 4 Tab 已满：地图/星迹/成就/我）。
中国坐标偏移存储 WGS-84，显示统一走 MapProvider.displayCoordinate（国内底图 GCJ-02 偏移）；轨迹端点与足迹点用同一转换，保证对齐。
离线示意曲线纯本地几何计算，无网络请求；底图沿用现有地图方案。
隐私Leg 存本地 SwiftData，随 App 数据一并保留；不上传、不采集，Data Not Collected 承诺不变。
无障碍 / RTL方式 chip / 按钮支持 Dynamic Type 与 VoiceOver；阿拉伯语下筛选条与 Sheet 走 RTL（见 §12）。
实现细节不在本 PRD坐标转换算法、SwiftData 迁移写法、曲线采样精度、动画帧率等属实现层，由开发在技术方案中定，本 PRD 只约束产品行为。

11验收标准 · QA Checklist

  • 轨迹视图
  • 地图 Tab 顶部可在「点亮 / 轨迹」间切换，状态正确保留。
  • 4 种方式各以规定线型/颜色/图标渲染，可肉眼区分。
  • 方式 chip 显隐即时生效，「全部」可一键全开/全关，且不改数据。
  • 点轨迹段浮出详情，含方式/起终点/日期/里程。
  • 无航段时显示引导空态 + ＋。
  • 航段录入
  • 方式 4 选 1，切换高亮正确。
  • 起终点可来自已点亮城市 / 搜索 / 地图选点。
  • 起终点未选齐时「保存」置灰；起点=终点、到达早于出发均被拦截。
  • 保存后即时上图并定位到该段。
  • 编辑/删除生效；删除有二次确认，且不影响足迹点亮。
  • 画线正确性
  • 跨 180° 经线的航段走反向短弧，不绕地球一圈。
  • 国内地点与足迹点在偏移底图上对齐（同一 MapProvider）。
  • 播放 / 统计（P1）
  • 播放按 departAt 顺序沿可见轨迹滑行一遍，可暂停。
  • 里程/段数统计正确，按方式细分，标注「直线估算」。
  • 平台 / 隐私
  • 全程无网络请求；杀进程重启数据不丢。
  • 阿拉伯语下筛选条/Sheet 正确 RTL；VoiceOver 可读方式与操作。
