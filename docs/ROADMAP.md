# Lumi 路线图（Roadmap）

把散落在 [`Lumi_v0_PRD.md`](Lumi_v0_PRD.md)、[`ARCHITECTURE.md`](ARCHITECTURE.md) 与各设计文档中的线索，
整理成以「**能上架的 MVP**」为锚点的分阶段路线。逐条需求与状态见 [`REQUIREMENTS.md`](REQUIREMENTS.md)；
专题设计见 [账号/迁移/交换/IM](DESIGN-accounts-and-exchange.md)、[变现](DESIGN-monetization.md)、
[BaaS 选型](DESIGN-baas-selection.md)；iOS 系统能力设想见 [`ios-native-capabilities.md`](ios-native-capabilities.md)。

> **北极星**：占据竞品最弱的「**记忆 / 共创**」象限——完整形态 = 明信片/交换日记 + 好友共享 + AI 故事片。
> **原则**：每阶段只在**前一阶段核心假设被验证后**才推进；未验证则修回路，而非堆功能。
> **平台**：**Android 是确定目标，短期先 iOS**——由此账号/同步走跨平台 BaaS（不走 CloudKit）、变现首发即接 RevenueCat。

## 阶段总览

| 阶段 | 主题 | 核心假设 / 目标 | 状态 |
|------|------|----------------|------|
| **Dogfood v0** | 世界点亮（集邮回路） | 「点亮那一下」足够爽，愿意手动记录 | ✅ 已交付 |
| **MVP** | 上架首版（iOS · 纯本地 · 无账号） | 真实用户愿留存、愿分享成果 | 🚧 收敛中 |
| **v1** | 账号 + 同步 + 跨平台变现 | 数据值得「带走 / 多端」，愿为增益付费 | 规划中 |
| **v1.x** | 共创第一步（明信片闭环 / 共同行程 / 交换日记） | 足迹有「被人看见 / 一起」的价值 | 规划中 |
| **v2** | 好友·IM·Android·本地模式·推荐·AI | 社交与智能放大记忆价值 | 远期 |

## Dogfood v0 — 世界点亮（✅ 已交付）

M1–M5 + 增强批次均已落地（暗夜霓虹地图点亮、Capture、离线 point-in-polygon、Timeline、Stats；

此为 dogfood 构建，下一步收敛成**可上架的 MVP**。

## MVP — 上架首版（iOS · 纯本地 · 无账号）

**目标**：用真实用户验证「集邮回路」的留存，以及「明信片分享」的自传播意愿。
**关键特征**：纯本地、无账号、无后端（沿用 v0 架构，成本近零）；登录/联网一律不需要。
**执行排期**（批次拆解 / 顺序 / 上架 Gate）见 [`MVP-PLAN.md`](MVP-PLAN.md)。

### 范围内（IN）— 大多已实现，重点是打磨到上架质量

| 模块 | MVP 内容 | 备注 |
|------|----------|------|
| 点亮 | 点阵地球 + 真实地图点国家快速点亮 + 选年份 | ✅ 已实现，体验打磨 |
| 时间线 | 列表 + 足迹编辑 + 详情 | ✅ 已实现 |
| 成就/徽章 | 3 列网格、置顶可取消、可点击看「怎么得到」 | ✅ 功能就绪；水晶徽章 + **6 枚大洲大师插画徽章**（06-27）已落地 |
| 心愿单 | 真实地图点选标记 + 个人页入口 | ✅ 已实现 |
| 相册导入 | 按位置自动生成足迹（城市/国家粒度） | ✅ 已实现 |
| 小组件 | 点亮计数 + 去年今日 + **去过的国旗（独立小组件）** + 设置页小组件介绍 | ✅ 全部已实现；文案跟随系统语言 |
| 明信片 | 导出/打印 + **口令/二维码「打开自动接收」**（纯本地带外传输） | 高价值自传播，无后端，纳入 MVP |
| 多语言 | 中/英/阿 + 阿语 RTL（跟随系统） | ✅ 已实现，英/阿待校对 |
| 设置 | 个人页顶部入口 + 语言（跟随系统） | ✅ 已实现 |

### 范围外（OUT，留给后续阶段）
账号/同步/迁移、好友/IM/通讯录邀请、共同行程/交换日记、推荐/行程规划、
本地模式（谷歌评价·美食家勋章）、Android、AI 故事片。

### 待定（Stretch，可压入 MVP 或紧随其后）
- **视频上传（≤3min）+ 时间线静音自动播放**：纯本地可做，但增存储/复杂度 → 建议作为 **Plus 功能 / 快速跟进**。
- **谷歌店铺 Share Extension 导入**：纯本地、价值高，但触及谷歌内容合规 → 建议 v1.x（或 MVP stretch）。

### 变现（MVP 决策）
纯本地即可卖 VIP（StoreKit 2，entitlement 在端上，恢复购买绑 Apple ID），**不需要账号**。
- **首发即接 RevenueCat**（Android 确定目标，避免日后重做计费层）。
- **建议**：MVP 的 paywall 保持**轻**（高清导出/打印、全部明信片模板、国旗等额外小组件、地图皮肤），
  核心集邮回路免费，先不伤留存验证；待留存站稳再加厚 Plus。
- 详见 [`DESIGN-monetization.md`](DESIGN-monetization.md)。

### 进入 v1 的门槛
真实用户**留存达标**（核心回路被验证）+ 出现明确的「多端 / 想带走数据」诉求。

## v1 — 账号 + 同步（BaaS）+ 跨平台变现

**前提**：MVP 留存成立。目标：让数据「多端可用、可带走」，并把变现做成跨平台。

- **账号**：BaaS Auth（Apple + Google 登录归一）；登录永远可选，不挡本地使用。
- **同步 + 迁移**：跨平台 BaaS（倾向 Supabase，见选型文档）；首次登录把本地 SwiftData 按 UUID **无损认领**，
  之后双向同步（本地仍作离线缓存）。
- **跨平台变现**：RevenueCat 把已购权益绑到账号，为后续 Android 共享 Plus 打底。
- 前置技术验证：[BaaS 同步 spike](DESIGN-baas-selection.md#5-poc-验证拍板前)。

## v1.x — 共创第一步

**前提**：有了身份与通道。把「分享」从带外升级为站内。

- **明信片站内闭环**：MVP 的口令/二维码 payload 改为站内直投（无需复制粘贴）。
- **共同行程**：双人/多人共享一个 `Trip`（BaaS 共享 + 行级权限）。
- **交换日记**：同一行程双方各自先写、结束后互相解锁（仪式感）。复用 `Trip`/`Card`/`accentRose` 打底。

## v2 — 好友 · IM · Android · 本地模式 · 推荐 · AI

**前提**：共创带来自然增长。完整产品形态收口（强依赖后端 + 合规）。

- **好友图谱 + App 内 IM**：发送地点/店铺/明信片消息；通讯录邀请。
- **Android 客户端**：复用同一 BaaS 与数据模型。
- **本地模式**：接谷歌地图店铺评价，按到店打卡点亮、产出「美食家」等品类勋章（与全球模式并存）。
- **推荐 / 行程规划**：推荐旅行地 / traveler；行程规划。
- **AI 旅行故事片**：基于足迹+照片+心情自动生成回顾（可端侧 Foundation Models）。
- **星球生活（探索向 💡）**：在本地 / 全球之外加「星球生活」模式——模拟登陆月球 / 火星等星球，
  做一本**星球护照**、盖各星球**登陆印章**。纯虚拟收集向，呼应护照 + 邮票 / 邮戳收集体系，
  适合装饰内购 / 季节限定。详见 [REQUIREMENTS §11](REQUIREMENTS.md#11-星球生活模拟登陆其他星球)。

## 跨阶段依赖与约束

| 能力 | 触发阶段 | 约束 |
|------|---------|------|
| 付费 Apple Developer Program | MVP（上架/IAP）起 | v0 免费自签 profile 7 天过期；上架与内购必需 |
| RevenueCat（跨平台 entitlement） | MVP 变现起 | 首发即接，避免上 Android 重做计费 |
| 跨平台 BaaS（**非 CloudKit**） | v1（账号/同步）起 | Android 确定目标 → 不投 CloudKit，避免二次迁移；倾向 Supabase |
| 后端实时通道 + 合规 | v2（IM/好友）起 | UGC 需举报/屏蔽；触发 Apple 2026 年中儿童安全/年龄分级问卷 |
| 谷歌内容合规 | v1.x（店铺导入）/ v2（本地模式）起 | 优先接收 share URL / 系统地点，谨慎用 Places API；复核商用条款 |
| 国内合规底图（高德 + 审图号） | 仅国内分发时 | 通过 `MapProvider` 换实现，不改业务层 |
| 后台 GPS 自动记录 | 未排期 | 与「手动点亮」哲学冲突，需重新评估 |
