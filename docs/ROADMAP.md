# Lumi 路线图（Roadmap）

本文档把散落在 [`Lumi_v0_PRD.md`](Lumi_v0_PRD.md) 与 [`ARCHITECTURE.md`](ARCHITECTURE.md)
中的「v0 之后」线索整理成分阶段路线。完整产品蓝图以《Lumi 产品与架构总览》为准，本文档仅
做工程侧的阶段拆解与依赖关系，随验证结果滚动更新。

> iOS 系统能力（小组件 / App Intents / Live Activity / Foundation Models 等）的接入设想，
> 见 [`ios-native-capabilities.md`](ios-native-capabilities.md)。

> 北极星：Lumi 定位于竞品最弱的「**记忆 / 共创**」象限——完整形态 = 交换日记 + AI 故事片 +
> 共创圈子。每个阶段只有在前一阶段的核心假设被验证后才推进，**未验证则修回路，而非加功能**。

## 阶段总览

| 阶段 | 主题 | 核心假设 / 目标 | 状态 |
|------|------|----------------|------|
| **v0** | 世界点亮（集邮回路） | 用户愿意手动记录每个足迹，「点亮那一下」足够爽 | ✅ 已交付 |
| **v0.x** | 怀念回路 + 交换日记 | 记下的足迹能产生「回看 / 被人看见」的持续动机 | ⏳ 待 v0 验证 |
| **v1** | 分享 / 导出 + 底图升级 | 点亮成果值得被带出 App（社交货币） | 规划中 |
| **v2** | 共创圈子 + AI 故事片 | 多人共创放大记忆价值 | 远期 |

---

## v0 — 世界点亮（✅ 已交付）

详见 PRD。M1–M5 全部完成：暗夜地图点亮 + Capture 录入 + 离线 point-in-polygon +
Timeline + Stats。进入 v0.x 的门槛：**作者本人连续 ≥ 2 周、平均每天自发记录 ≥ 1 个足迹**。

收尾待确认项（不阻塞进入 v0.x，见 ARCHITECTURE §7）：
- `photoAssetID` 失效策略（占位 vs 提示补图 vs 自动清理引用）
- Timeline 是否需要编辑（当前仅删除 + 只读详情）

---

## v0.x — 怀念回路 + 交换日记

**前提**：v0 验证假设成立。目标是从「记录」走向「回看 / 共创」的第一步。

代码已埋好的打底点：`Trip` 模型（按行程回顾）、`Card` 明信片卡持久化（导出图缓存 / 多模板）、
`accentRose` 设计令牌（标注用途「情感 / 交换日记」）。

- **怀念回路**
  - 「去年今日」/ 年度回顾：按 `visitedAt` 聚合历史足迹，定期推送回看入口。
  - 行程回顾：基于 `Trip` 把散点足迹归并为一段旅程时间线。
- **交换日记（最小形态）**
  - 明信片卡分享给指定对方 / 双人共写一段旅程。
  - 依赖：需要轻量身份与数据交换通道 → 触及账号 / 同步（见「跨阶段依赖」）。

## v1 — 分享 / 导出 + 底图升级

**前提**：怀念回路证明足迹有「再消费」价值。目标是让点亮成果成为社交货币。

- **分享 / 导出**：基于 `Card` 渲染可分享图 / 长图 / 印刷件（明信片卡本就为此打底）。
- **下钻精度**：省 / 市级区域着色；英国等国家城市下钻（v0 已确认「城市 = 点状打卡」规则，
  此处升级为区域着色）。
- **底图升级**：通过 `MapProvider` 抽象切换 Mapbox（海外美学）；国内分发时切高德 +
  审图号（合规底图）。上层着色 / 落点逻辑不动。

## v2 — 共创圈子 + AI 故事片

**前提**：分享带来自然增长。完整产品形态的收口。

- **共创圈子**：多人围绕同一地图 / 行程共创。
- **AI 旅行故事片**：基于足迹 + 照片 + 心情自动生成回顾叙事。
- 强依赖云端基础设施（账号、同步、内容生成服务）。

## 跨阶段依赖与约束

| 能力 | 触发阶段 | 约束 |
|------|---------|------|
| 账号体系 / 云同步 / 推送 | v0.x（交换日记）起 | 一旦要做即需**付费 Apple Developer Program**（v0 用免费自签，profile 7 天过期） |
| 国内合规底图（高德 + 审图号） | v1（仅国内分发时） | 通过 `MapProvider` 换实现，不改业务层 |
| 后台 GPS 自动记录 | 未排期 | 与「手动点亮」的产品哲学冲突，需重新评估 |
| 多媒体（多图 / 视频 / 语音 / 涂鸦） | v1+ 按需 | v0 刻意限制为单图 |

## 维护说明

本路线图随每阶段验证结果滚动修订；阶段顺序服从「假设验证」而非功能堆叠。新增阶段或调整优先级时，
同步更新本表与 README 里程碑表。
