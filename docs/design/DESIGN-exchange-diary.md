# Lumi · 交换日记（Exchange Diary）
**功能规格说明 · v1.0（工程就绪）**

> 适用范围：Lumi v0.x 差异化功能。依赖已上线的 Footprint / Trip / 旅伴体系。
> 关联文档：《Lumi v0 — 世界点亮 MVP》（v0.3）、《Lumi 产品与架构总览》。
> 原型：`lumi_exchange_diary.html`（书架 + 内页对开）、`lumi_diary_create_flow.html`（0→1 创建流程）。
> 线框稿：`Lumi/diary/[页面名]`（Axure，人工维护）。

---

## 1. 背景与问题描述

Lumi 的产品定位落在竞品最弱的「记忆 / 共创」象限，而**交换日记是这个象限里最独特、最难被抄的功能**——它是护城河，不是锦上添花。

真实世界的交换日记机制：两人各自私密地写，都写完后同时揭晓，那个"原来你当时是这么想的"的瞬间就是全部的价值。有时一致，有时意外地不同。

它生成的是**一个人做不出来的记忆**：对情侣、朋友成立，对**亲子**尤其动人——孩子那一版可以是一段语音、一张涂鸦，贴在你的文字旁边。

**核心约束**：远程交换需要账号 + 后端 + 好友关系（且需付费 Apple Developer Program），这会把护城河功能一直往后拖。但真实的交换日记本来就是**把本子递给对方**——因此 v1 采用「本机传递」模式，零后端即可成立（见 §5.3）。

---

## 2. 目标

**产品目标**
- 让用户产出**共同的记忆资产**，而非各自的独立日记。
- 制造"拆封"这一情绪高光时刻，形成回访动机。
- 通过"必须拉旅伴一起写"带来天然的留存与拉新。

**成功信号**
- 创建一本日记后，作者本人在 7 天内完成 ≥ 1 页的双方书写与揭晓。
- 亲子场景下孩子愿意用语音/涂鸦参与（非文字输入占比 > 30%）。

**非目标**：见 §8。

## 4. 核心模型：本 / 页 / 半页

**这是整个功能的地基，粒度错了功能会卡死。**

| 层级 | 绑定 | 说明 |
|---|---|---|
| **本 DiaryBook** | = 一段 **Trip** × 一位交换对象 | 一本书需要一个主题，旅程天然就是它。封面 / 日期 / 地点 / 书脊配色全部**自动派生**，用户零填写。 |
| **页 DiaryPage** | = 一个 **Footprint**（默认） | **允许自由页**：有些心情不属于任何地点（飞机上、回家路上），强制挂靠会很别扭。 |
| **半页 DiaryEntry** | = 一位作者在一页上的内容 | 一页含两个 Entry（我 / TA）。**揭晓发生在「页」级别。** |

### 4.1 绑定关系（三档）

- ✅ **本必须绑定 Trip** —— 不提供"完全独立的本"的入口。
- ✅ **页默认绑定 Footprint，允许自由页**（`footprint == nil`）。
- ⚠️ **完全独立的本：技术上支持，但不在入口上鼓励。**
  > **理由（重要）**：一旦交换日记能完全脱离足迹，Lumi 就滑向"通用日记 App"——那个赛道极其拥挤，且丢掉了本产品的护城河（地图 + 点亮 + 旅伴）。让它长在足迹上，它才是别人抄不走的东西。

### 4.2 为什么不按「足迹」建本

一趟迪拜之旅有 10 个足迹，若按足迹交换，就要 10 次"双方都写完才揭晓"→ **交换疲劳**，大部分会永远卡在"等 TA 写"。一本 = 一段旅程，才是真实交换日记的样子：一个本子，来回传，每页两种笔迹。

## 5. 核心逻辑 / 状态机

### 5.1 页状态机（揭晓在页级别）

```
[空 Empty]
   │ 我写完并封存
   ▼
[我已封存 MineSealed] ──TA 写完并封存──> [可揭晓 Revealable]
   │                                            │ 任一方点击拆封
   │ （TA 迟迟不写）                              ▼
   │                                      [已揭晓 Revealed]
   ▼
[我随时可看自己那半页]  ← 守卫规则（见 5.2）
```

- 若 TA 先写：进入 `[TA 已封存]`，对我显示「该你了」，TA 的半页保持封印。
- 揭晓后双方半页永久可见，不可再改。

### 5.2 守卫规则（必须实现）

> **永远不扣押用户自己写的内容。**
> 用户随时能看自己写的那半页；被封的**只有对方那半页**。

**理由**：若对方一直不写，用户自己那半也锁着 → 用户会感到"我的东西被人质了"，是强挫败点。

**兜底**：超过 N 天（默认 14 天）未等到对方，提供「先看我的，TA 写了再通知你」，并可温和提醒对方。

### 5.3 交换模式（两种，共用同一套 本/页/封印 模型）

| 模式 | 机制 | 依赖 | v1 |
|---|---|---|---|
| **本机传递 Hand-off** | 我写完 → 封存 → **把手机递给旅伴** → TA 在我手机上写 → 一起揭晓 | **零后端、零账号、零 $99** | ✅ v1 做 |
| **远程交换 Remote** | 双方各自设备书写，云端同步揭晓状态 | 账号 + 后端 + 好友关系（需付费 Developer Program） | ❌ 社交阶段 |

**本机传递是本 PRD 最关键的工程决策**：它把护城河功能从"要等社交基建"变成"下个版本就能做"，且比远程版**更还原"传本子"的仪式感**。对亲子场景尤其自然——孩子本来就没账号，就是接过手机写字 / 涂鸦 / 录语音。

### 5.4 旅伴分档（Companion）

现有 `Footprint.companions: [String]` 升级为两档，**两档并存**：

| 档位 | 能力 | 场景 |
|---|---|---|
| **纯名字标签**（现状保留） | 可标注，**可走本机传递交换** | 小孩、不装 App 的长辈 |
| **已连接好友** | 可走远程交换 | 成年旅伴 |

**旅伴字段天然是邀请入口**：标了一个人、TA 还没在 Lumi 上 → 弹「邀请 TA 一起写这段旅程」。这是自带拉新的具体挂载点。

## 6. UI 设计规格

> 风格：浅色 neo-brutalist（暖米底 + 粗黑描边 + 硬阴影）。**火漆封印（wax seal）是本功能的签名视觉**——它把交换日记接进 Lumi 已有的邮政隐喻（明信片 / 邮票 / 邮戳 / 护照），而不是另起一个"日记 App"的皮。

### 6.1 创建流程（3 次点击落到写作页）

**三个入口**
1. **足迹详情页的邀请卡**（主推）——旅伴信息已在场，最自然。
2. Me → 交换日记 → `+ 新建`（此入口需多一步「选旅程」）。
3. **系统助推**：旅程结束 2 天后推送「XX 之旅结束了，要和 TA 一起写下来吗？」

**步骤**（从足迹入口进入时，Step 1 自动跳过）

| Step | 内容 | 关键设计 |
|---|---|---|
| 1 · 选旅程 | 列出有足迹的旅程：名称 + 日期 + 足迹数 + 旅伴头像 | 从足迹入口进入时自动推断，跳过 |
| 2 · 选交换对象 | 列出**这段旅程已有的旅伴**，按档位显示 `☁️ 远程交换` / `📱 本机传递` | 未装 App 的旅伴灰显 + 软邀请入口 |
| 3 · 选页 | 该旅程所有足迹→页，**默认全选**，可取消 | 必须显示 **「不用每页都写，随时可以补 ✦」** |
| 4 · 封面 | 旅程名 + 日期 + 地点 + 书脊配色**全自动生成** | 仅提供「换个颜色」，**不让用户填表** |

→ 成书后**直接进入第一页的写作页**（不停在"一本空书"）。

**设计守则**
- ① **创建到落笔 ≤ 3 次点击。** 别让用户创建完空书再自己找地方写——那本书大概率永远是空的。
- ② **「不用每页都写」必须出现。** "要写 6 篇"的心理负担是本功能最大的流失点。

### 6.2 书架（Me → 交换日记）

**卡片形式，非列表。** 卡面元素：书脊配色条（随旅程）、旅程名、日期范围 + 地点 + 足迹数、**两人头像交叠**、页数进度、状态徽标。

**卡片真正的信息量在「状态」**：

| 状态 | 卡面表现 |
|---|---|
| 待我写 | 亮色 · `✍️ 该你了` |
| 已写，等 TA | `🔒 已封存 · 等 TA` |
| **可揭晓** | **红边 + 呼吸的火漆封蜡 + `✦ 可揭晓`** ← 全屏最抢眼，是回访钩子 |
| 已揭晓 | 平静 · `N 页 · 已拆封` |
| 空本子 | 灰 · `还没有人写过` + 邀请旅伴入口 |

**排序**：可揭晓 > 待我写 > 等 TA > 已揭晓 > 空本。

### 6.3 内页对开（Spread）

- 一页 = 一个足迹，**左页我 / 右页 TA**，纸张横线纹理。
- 页眉：`第 N 页 · 地点名` + 日期 + 状态。
- 未揭晓：**对方那半页盖火漆封印**；我那半页**正常可读**（守卫规则的可视化）。
- 已揭晓：双方内容并置，孩子那半可为语音条 / 涂鸦。

### 6.4 写作页（Compose）

- 左我右 TA（TA 那半盖蜡，提示「等你写完后把手机递给她」）。
- 输入工具三选：**✍️ 文字 / 🎨 涂鸦 / 🎤 语音**（后两者是**给孩子的**，用 PencilKit + 录音）。
- 主按钮：**「封存我的这半页 🔒」**。

### 6.5 空状态（首次打开必须教学）

大号火漆封印 + 标题「还没有一本日记」+ 一句话机制说明「各自写，**都写完才能拆封**——看看对方当时在想什么」+ 三步图示 `✍️ 你写 → 🔒 封存 → ✦ 一起拆`。

> **这个机制不解释，用户不会自己发现。**

## 7. 边界情况处理

| 情况 | 处理方式 |
|---|---|
| 对方长期不写 | **我那半页始终可读**（守卫规则）；超 14 天提供「先看我的，TA 写了再通知你」 |
| 旅伴只是名字、未装 App | 自动走本机传递模式；同时给出软邀请入口，不阻断 |
| 一段旅程想和多人各写一本 | 支持：`Book = Trip × Partner`，同一 Trip 可有多本 |
| 想写不属于任何地点的一页 | 支持**自由页**（`footprint == nil`），手动新增 |
| 足迹被删除 | 对应页保留（降级为自由页），已写内容**不丢** |
| 揭晓后想修改 | 不允许（揭晓即定格，保护"当时的想法"的真实性） |
| 本机传递时误触 | 递出前进入「传递模式」：仅显示 TA 的空白半页，**我的内容不可见**，防止提前偷看 |
| 一页只有一方写、用户想删本 | 允许删本；提示"已写的内容将一并删除" |
| 离线 | 本机传递模式**全功能离线可用** |

## 8. 非目标（Not in Scope）

- **远程交换**（需账号 + 后端 + 好友关系 + 付费 Developer Program）→ 社交阶段
- 多人（>2）共写同一本
- 揭晓后编辑 / 版本历史
- 日记内容的对外分享 / 导出（可后置）
- 完全脱离 Trip 的独立日记本入口（技术支持但不鼓励，见 §4.1）
- AI 生成日记内容（与"真实笔迹"的产品气质冲突）

## 9. 埋点事件

| 事件名 | 触发时机 | 关键属性 |
|---|---|---|
| `diary_entry_point_shown` | 足迹详情展示邀请卡 | trip_id |
| `diary_create_started` | 进入创建流程 | source（footprint / me / push） |
| `diary_create_abandoned` | 未成书退出 | last_step |
| `diary_book_created` | 成书 | trip_id, mode（handoff / remote）, page_count |
| `diary_entry_sealed` | 封存一个半页 | book_id, page_id, input_type（text / draw / voice） |
| `diary_handoff_started` | 进入传递模式 | book_id |

| `diary_invite_sent` | 发出旅伴邀请 | companion_name |

**北极星指标**：`diary_page_revealed` 的发生率与 `days_to_reveal` 中位数。

## 10. 验收标准

**① 创建流程**
- [ ] 足迹详情页展示「和 TA 一起写这段旅程」邀请卡（有旅伴时）
- [ ] 从足迹入口创建，**≤ 3 次点击可落到写作页**
- [ ] 选对象页正确区分「已连接好友 / 纯名字（本机传递） / 未装 App」
- [ ] 选页页默认全选，且显示「不用每页都写，随时可以补」
- [ ] 封面自动生成，用户无需填写任何字段
- [ ] 成书后直接进入第一页写作页

**② 书架**
- [ ] 五种状态卡片显示正确，且「可揭晓」最醒目（呼吸封蜡）
- [ ] 卡片显示两人头像交叠、页数进度、旅程信息
- [ ] 排序：可揭晓 > 待我写 > 等 TA > 已揭晓 > 空本

**③ 内页 / 揭晓**
- [ ] 未揭晓时，**我自己的半页始终可读**（守卫规则）
- [ ] 未揭晓时，对方半页显示火漆封印，不可窥见内容
- [ ] 双方均封存后，页状态变为「可揭晓」
- [ ] 拆封后双方内容并置显示，不可再编辑

**④ 写作 / 传递**
- [ ] 支持文字 / 涂鸦 / 语音三种输入
- [ ] 「封存我的这半页」后内容落库且不可改
- [ ] 传递模式下**我的内容不可见**，仅显示对方空白半页
- [ ] 离线状态下本机传递全流程可用

**⑤ 空状态**
- [ ] 首次进入展示机制教学（火漆 + 三步图示）

## 12. 数据模型（SwiftData）

```
DiaryBook
├─ id: UUID
├─ trip: Trip                    ← 必绑（§4.1）
├─ partnerName: String           ← 纯名字档
├─ partnerFriendID: String?      ← 已连接好友档（远程模式才有）
├─ mode: .handoff | .remote
├─ spineColor: String            ← 自动派生
├─ createdAt: Date
└─ pages: [DiaryPage]

DiaryPage
├─ id: UUID
├─ book: DiaryBook
├─ footprint: Footprint?         ← 可为 nil = 自由页（§4.1）
├─ orderIndex: Int
├─ revealedAt: Date?             ← nil 即未揭晓
└─ entries: [DiaryEntry]         ← 最多 2（我 / TA）

DiaryEntry                        ← 「半页」
├─ id: UUID
├─ page: DiaryPage
├─ authorIsOwner: Bool           ← true = 我，false = 交换对象
├─ text: String?
├─ drawingData: Data?            ← PencilKit
├─ voiceFilename: String?
├─ sealedAt: Date?               ← nil 即草稿；非 nil 即已封存
└─ createdAt: Date
```

**页状态派生规则（零冗余存储）**
- `entries` 为空 → 空
- 仅我方 `sealedAt != nil` → 我已封存 · 等 TA
- 仅对方 `sealedAt != nil` → 该你了
- 双方 `sealedAt != nil` 且 `revealedAt == nil` → **可揭晓**
- `revealedAt != nil` → 已揭晓

## 待确认项（不自行假设）

1. **传递模式的防偷看强度**：是否需要在递出前加一道确认/锁屏（防止对方翻看我已封存的内容）？
2. **语音时长上限**与存储策略（本地文件 vs SwiftData 外部存储）。
3. **超时兜底天数**：默认 14 天是否合适？
4. **一页两人都写完但没人点"拆封"**：是否在 N 天后自动揭晓？（建议不自动——保留仪式感）
